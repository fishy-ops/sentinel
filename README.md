# Sentinel

Sentinel is a transaction fraud triage service with reproducible synthetic data and an authenticated transaction API.

## Quickstart

```sh
uv sync
make data
uv run python -m sentinel.api.keys create --scopes ingest,read --name local
make run
uv run pytest -q
```

Generated train, val, eval, and finetune files are written to `data/generated/`.
Set `SENTINEL_DATABASE_URL` to choose a SQLite database; the default is `sqlite:///./sentinel.db`. Send the printed key in `X-API-Key` when calling `/v1` endpoints. Set `SENTINEL_RATE_PER_SECOND`, `SENTINEL_RATE_BURST`, and `SENTINEL_MAX_BODY_BYTES` to adjust request limits.

## Detection and evaluation

```sh
make data train eval-flags
```

Training fits an IsolationForest on transaction features from the train split without using labels. Fraud labels in the val split select its score threshold. The eval split is used only to report metrics. Results and the precision–recall plot are in `evals/results/` and `docs/results/`; PR-AUC is average precision. Misclassified rows, including their features and reasons, are written to the ignored `evals/failures/flags.jsonl`.

The API uses named rules by default. Set `SENTINEL_MODEL_ARTIFACT=models/iforest.joblib` to combine those rules with the trained forest. Each flag records its reasons, score, and model version. The model file is generated by `make train`; its JSON sidecar records the feature list, threshold, training data hash, and library version.

`GET /v1/audit/verify` returns the count and head hash of the chain before its own audit entry is appended. Store both outside the database to detect a truncated tail during a later check.
